# ใช้งานระบบจริงบนเว็บด้วย Render

ติดตั้งระบบเต็มรูปแบบ (API + PostgreSQL + หน้าเว็บ + สร้าง Word/PDF) บน [Render](https://render.com) จาก GitHub
ไม่ต้องดูแลเซิร์ฟเวอร์เอง ได้ลิงก์ `https://<ชื่อ>.onrender.com` พร้อม HTTPS

[![Deploy to Render](https://render.com/images/deploy-to-render-button.svg)](https://render.com/deploy?repo=https://github.com/Pongpitakzaa/PROCUREMENT-)

> **เลือกให้เหมาะกับข้อมูล:** Render เป็นผู้ให้บริการต่างประเทศ (ข้อมูลอยู่ที่ศูนย์ข้อมูลสิงคโปร์)
> เหมาะกับการทดลองใช้งาน อบรม หรือหน่วยงานที่อนุญาตให้ใช้คลาวด์ต่างประเทศได้
> ถ้าจะเก็บข้อมูลราชการ/ข้อมูลส่วนบุคคลจริง ควรติดตั้งบนเซิร์ฟเวอร์ของหน่วยงานหรือคลาวด์ภาครัฐ (GDCC)
> ตาม [deploy/README.md](README.md) และปรึกษาเจ้าหน้าที่คุ้มครองข้อมูลส่วนบุคคล (DPO)

## ขั้นตอน (ประมาณ 15 นาที — ส่วนใหญ่คือรอ build)

1. สมัคร/เข้าสู่ระบบ https://dashboard.render.com ด้วยบัญชี GitHub
2. กดปุ่ม **Deploy to Render** ด้านบน (หรือ **New → Blueprint** แล้วเลือก repository นี้)
   Render อ่าน `render.yaml` แล้วแสดงสิ่งที่จะสร้าง: web service `procurement` และฐานข้อมูล `procurement-db`
3. กรอกค่าที่ Render ถาม (ใช้สร้างผู้ดูแลระบบคนแรกอัตโนมัติ):

   | ค่า | ตัวอย่าง | หมายเหตุ |
   |---|---|---|
   | `PROC_BOOTSTRAP_ADMIN_USERNAME` | `itadmin` | a-z 0-9 _ . - ยาว 3–60 ตัว |
   | `PROC_BOOTSTRAP_ADMIN_PASSWORD` | (ตั้งเอง) | ≥ 12 ตัว มีทั้งตัวอักษรและตัวเลข และไม่มีชื่อผู้ใช้อยู่ในรหัสผ่าน |
   | `PROC_BOOTSTRAP_ADMIN_NAME` | `นายสมชาย ใจดี` | คำนำหน้า ชื่อ นามสกุล |
   | `PROC_BOOTSTRAP_ADMIN_CITIZEN_ID` | 13 หลัก | เก็บแบบเข้ารหัส AES-256-GCM |
   | `PROC_BOOTSTRAP_DEPARTMENT_NAME` | `กองพัสดุ สำนักงาน…` | หน่วยงานแรกของระบบ |
   | `PROC_LINE_CHANNEL_ACCESS_TOKEN` | (เว้นว่างได้) | แจ้งเตือน LINE — ใส่ทีหลังได้ ดู [LINE.md](LINE.md) |
   | `PROC_LINE_CHANNEL_SECRET` | (เว้นว่างได้) | ใช้ตรวจลายเซ็น webhook ของ LINE |

4. กด **Apply** แล้วรอ build (ครั้งแรก 10–15 นาที เพราะติดตั้ง LibreOffice)
5. เมื่อสถานะเป็น **Live** เปิดลิงก์ของ service `procurement` → เข้าสู่ระบบด้วยบัญชีจากข้อ 3
6. หลังเข้าได้แล้ว:
   - เมนูชื่อผู้ใช้ → **เปลี่ยนรหัสผ่าน**
   - ใน Render: service `procurement` → **Environment** → ลบ `PROC_BOOTSTRAP_ADMIN_PASSWORD` (ไม่ใช้แล้ว ระบบสร้างผู้ดูแลเฉพาะตอนยังไม่มีผู้ใช้)
   - **ผู้ดูแลระบบ → ผู้ใช้งาน**: สร้างบัญชีเจ้าหน้าที่ หัวหน้าเจ้าหน้าที่ ผู้บริหาร
   - **ผู้ดูแลระบบ → แบบฟอร์มกรมบัญชีกลาง**: อัปโหลดแบบฟอร์ม แล้วให้หัวหน้าเจ้าหน้าที่รับรอง
   - **แจ้งเตือน LINE**: ตั้งค่าตาม [LINE.md](LINE.md) (10 นาที)

ถ้าสร้างผู้ดูแลไม่สำเร็จ (เช่น รหัสผ่านไม่ผ่านนโยบาย) ดูสาเหตุที่ **Logs** (บรรทัด `init-db:`) แก้ค่าใน **Environment** แล้ว **Manual Deploy**

## ลืมรหัสผ่าน / ไม่มีผู้ดูแลระบบ

| สถานการณ์ | วิธีแก้ (ไม่ต้องใช้ Shell ใช้ได้บนแผนฟรี) |
|---|---|
| ลืมรหัสผ่านผู้ใช้คนใดก็ได้ | **Environment** → Add `PROC_RESET_PASSWORD_FOR` = ชื่อผู้ใช้ และ `PROC_RESET_PASSWORD_TO` = รหัสผ่านใหม่ (≥ 12 ตัว มีตัวอักษรและตัวเลข) → **Save Changes** → รอ deploy → เข้าสู่ระบบด้วยรหัสใหม่ → **ลบทั้งสองค่าออกทันที** (ไม่อย่างนั้นจะรีเซ็ตซ้ำทุกครั้งที่ deploy) |
| ไม่อยากตั้งรหัสเอง | ใส่เฉพาะ `PROC_RESET_PASSWORD_FOR` ระบบสุ่มรหัสให้และแสดงใน **Logs** บรรทัด `init-db: รีเซ็ตรหัสผ่าน…` |
| ระบบยังไม่มีผู้ใช้เลย (สร้าง service โดยไม่ผ่าน Blueprint) | ใส่ `PROC_BOOTSTRAP_ADMIN_USERNAME` / `_PASSWORD` / `_NAME` / `_CITIZEN_ID` / `PROC_BOOTSTRAP_DEPARTMENT_NAME` ตามตารางข้อ 3 → Save → ระบบสร้างผู้ดูแลให้ตอน deploy (ทำงานเฉพาะเมื่อยังไม่มีผู้ใช้) |
| แผน starter ขึ้นไป | ใช้แท็บ **Shell**: `python -m app.cli reset-password <ชื่อผู้ใช้>` ก็ได้ |

ทุกการรีเซ็ตบันทึกใน Audit Log (`PASSWORD_RESET`, via `env`) และ token เดิมของผู้ใช้นั้นใช้ไม่ได้ทันที

## สิ่งที่ Render ทำให้อัตโนมัติ

- **HTTPS** และโดเมน `*.onrender.com` (ผูกโดเมนของหน่วยงานได้ที่ **Settings → Custom Domains**)
- **ค่าลับ** JWT และกุญแจเข้ารหัส สุ่มให้ตอนสร้าง ไม่มีใน repository
- **ฐานข้อมูล** สร้างตารางและข้อมูลอ้างอิงเมื่อเริ่มครั้งแรก (`init-db`) และรับการเชื่อมต่อเฉพาะภายใน Render
- **อัปเดตอัตโนมัติ** ทุกครั้งที่ merge เข้า `main`

## แผนฟรีกับการใช้งานจริง

| เรื่อง | แผนฟรี | ใช้งานจริง (แนะนำ) |
|---|---|---|
| Web service | หลับเมื่อไม่มีผู้ใช้ 15 นาที เปิดครั้งถัดไปรอประมาณ 1 นาที | `starter` ขึ้นไป (เปิดตลอด) |
| ฐานข้อมูล | 1 GB **หมดอายุ 30 วัน** (ลบหลังจากนั้นอีก 14 วัน) | `basic-256mb` ขึ้นไป |
| ไฟล์สำรองในระบบ (เมนูสำรอง/กู้คืน) | หายเมื่อ service เริ่มใหม่ | ใช้การสำรองฐานข้อมูลของ Render ร่วมด้วย หรือเพิ่ม Disk |

ราคาและเงื่อนไขเปลี่ยนได้ ตรวจที่ https://render.com/pricing ก่อนตัดสินใจ
เปลี่ยนแผนได้ที่หน้า service/ฐานข้อมูลใน Render หรือแก้ `plan:` ใน `render.yaml`

แบบฟอร์มกรมบัญชีกลางที่อัปโหลด**ไม่หาย**เมื่อ service เริ่มใหม่: ระบบเก็บสำเนาในฐานข้อมูลและสร้างไฟล์คืนให้เอง
(ตรวจ SHA-256 กับฉบับที่รับรองทุกครั้ง) ไฟล์เอกสารที่สร้างแล้ว (Word/PDF) สร้างใหม่ได้ทุกเมื่อจากหน้าโครงการ

## ข้อควรระวัง

- **ห้ามเปลี่ยน `PROC_DATA_KEY` และ `PROC_BACKUP_KEY`** หลังเริ่มใช้งาน: เลขประจำตัวประชาชน/บัญชีธนาคารที่เข้ารหัสไว้
  และไฟล์สำรองจะถอดรหัสไม่ได้ — คัดลอกค่าทั้งสองจาก **Environment** ไปเก็บในที่ปลอดภัยนอก Render
- หน่วยความจำ 512 MB (แผนฟรี/starter) พอสำหรับผู้ใช้จำนวนน้อย ถ้าสร้าง PDF พร้อมกันหลายคนให้ขยายเป็น `standard`
